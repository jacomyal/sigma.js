Sigma handles mouse and touch interactions out of the box and emits events you can listen to.

## Built-in interactions

By default, sigma supports these interactions:

| Interaction | Mouse                             | Touch                |
| ----------- | --------------------------------- | -------------------- |
| **Pan**     | Drag the background               | Drag with one finger |
| **Zoom**    | Scroll wheel                      | Pinch                |
| **Rotate**  | Right-click drag                  | Two-finger rotate    |
| **Hover**   | Move cursor over a node           | -                    |
| **Click**   | Click a node, edge, or background | Tap                  |

Some of these interactions can be enabled or disabled via settings:

```typescript
new Sigma(graph, container, {
  settings: {
    enableCameraZooming: true, // Scroll/pinch to zoom
    enableCameraPanning: true, // Drag to pan
    enableCameraRotation: true, // Right-click drag / two-finger rotate
  },
});
```

### Graph gestures vs. page scrolling

When sigma is embedded in a scrollable page (such as all examples in this very website), wheel and touch gestures are
ambiguous: should they zoom the graph, or scroll the page? The `gestureTarget` setting routes them:

- `"graph"` (default): all gestures go to the graph. The page never scrolls over the stage. Best for full-screen
  applications.
- `"shared"`: plain gestures go to the page, and the graph is reached with <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + scroll, or
  two-finger touch. A hint overlay tells users how, with its texts customizable through the `sharedGestureWheelMessage`,
  `sharedGestureAppleWheelMessage` and `sharedGestureTouchMessage` settings. Best for graphs embedded in articles or
  dashboards.
- `"page"`: wheel and touch gestures all go to the page. Clicks, taps and mouse drag-panning still reach the graph.

See the [settings reference](/reference/settings/#gesture-target) for details.

## Listening for events

Sigma emits events when users interact with nodes, edges, or the stage (background). Listen with `renderer.on()`:

```typescript
renderer.on("clickNode", ({ node, event }) => {
  console.log("Clicked node", node);
  console.log("Position", event.x, event.y);
  console.log("Native event", event.original);
});

renderer.on("enterNode", ({ node }) => {
  console.log("Entering node", node);
});

renderer.on("leaveNode", ({ node }) => {
  console.log("Entering node", node);
});

renderer.on("clickStage", () => {
  // User clicked the background, e.g. deselect all
});
```

Every event payload includes an `event` object with `x`, `y` coordinates and `original` (the native `MouseEvent` or `TouchEvent`).

## Enabling edge events

Edge events are disabled by default for performance (edge hit detection requires extra GPU work). Enable them with:

```typescript
new Sigma(graph, container, {
  settings: { enableEdgeEvents: true },
});
```
